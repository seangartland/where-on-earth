Create a file src/cities.js in this directory (an ES module, used with Three.js r150+ via import). Do not touch any other file.

Context: cities.js loads assets/cities.json, an array of ~10000 objects shaped like {"name":"Shanghai","lat":31.2222,"lng":121.4581,"pop":24874500}. lat/lng are degrees.

Requirements:
1. Top of file: `import * as THREE from 'three';`
2. A function to fetch assets/cities.json via fetch() (relative path "./assets/cities.json" from the page root — assume fetch works, this runs in a browser/vite context).
3. Convert each city's lat/lng to a 3D position on a sphere of radius `globeRadius` using the standard formula:
   lat/lng in degrees -> radians; 
   phi = (90 - lat) * (Math.PI/180); theta = (lng + 180) * (Math.PI/180);
   x = -globeRadius * Math.sin(phi) * Math.cos(theta)
   y = globeRadius * Math.cos(phi)
   z = globeRadius * Math.sin(phi) * Math.sin(theta)
   (This is the same convention typically used for lat/lng-to-sphere mapping with Three.js globes where texture seam is at the antimeridian — if you know a more standard convention for THREE.SphereGeometry UV mapping, use that instead, but be internally consistent.)
4. Build a THREE.BufferGeometry with a position attribute (Float32Array, 3 per city) and a custom per-vertex "size" attribute (Float32Array, 1 per city) scaled by population: use something like `size = baseSize + Math.log10(pop) * scaleFactor`, clamped so the largest cities (pop ~25,000,000) render at about 3-4px and the smallest at about 1px. Tune constants so this holds given real population values from ~5000 (small towns) to ~25000000 (megacities).
5. Generate a circular sprite texture procedurally on an off-screen <canvas> (e.g. 32x32 or 64x64): draw a radial gradient, white/light-gold center fading to transparent, to produce a soft round dot (not a hard-edged circle). Turn that canvas into a THREE.CanvasTexture.
6. Create a THREE.ShaderMaterial or THREE.PointsMaterial:
   - If using PointsMaterial: set `map` to the circular sprite texture, `size` ~2-4 (px), `sizeAttenuation: true`, `transparent: true`, `opacity` in the 0.3-0.5 range (pick 0.4 as the default "medium brightness"), `color` a soft white or light gold (e.g. 0xfff4d6 or 0xffffff), `depthWrite: false`, `blending: THREE.AdditiveBlending` is fine for a subtle glow but don't make it look bright/photorealistic — test opacity 0.4 as baseline.
   - Per-city size variance (step 4) requires either a ShaderMaterial with a custom per-vertex size attribute read in the vertex shader (standard THREE.js point-size-attenuation vertex/fragment shader pattern, gl_PointSize = size * (scale / -mvPosition.z) or similar, sampling the sprite texture in the fragment shader with a radial soft alpha falloff), OR PointsMaterial with a single fixed size if a custom shader is too complex — prefer the ShaderMaterial approach for proper per-city size variance and size attenuation with zoom, since that's specified as a requirement.
7. Build a THREE.Points object from the geometry + material.
8. Export `export function addCitiesToGlobe(scene, globeRadius)` — it must: fetch the JSON, build geometry/material/points as above, add the THREE.Points object to `scene`, and return the THREE.Points object (or a Promise resolving to it, since fetch is async — either is fine, just be consistent and make it easy for a caller to await).
9. No labels, no text, no DOM elements besides the throwaway canvas used to build the texture. No day/night variation. No terrain/satellite imagery concepts — just dots.
10. Keep the file self-contained, reasonably commented only where non-obvious (the lat/lng-to-sphere formula, the shader).

Write ONLY to src/cities.js inside this working directory. Do not modify main.js, index.html, or anything else. When done, print the final file path and a 3-5 line summary of what you built.
